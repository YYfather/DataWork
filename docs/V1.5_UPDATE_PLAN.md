# DataWork V1.5 更新计划书

> 目标版本：`1.5.0`
> 当前基线：`1.0.0`
> 文档状态：功能实现与本地发布门禁已完成（2026-07-23）
> 适用范围：完整源码 `main` 分支；服务器部署 `Web` 分支在用户明确执行发布后由同一验收版本同步

## 1. 更新目标

V1.5 已在专业模式中加入“配对映射计算”与“联合因变量分组”，使 DataWork 能在一个分析计划内完成 CK/T 一对一配对、处理相对对照的增量计算，以及按年份、时期或其他拆分条件批量执行统计模型。

本次更新必须同时满足以下目标：

- 复现农业参考脚本中的 T1/CK1、T2/CK2、T3/CK3 配对流程；
- 允许用户为配对结果定义最多 10 个计算列，并自定义列名；
- 允许配对计算列作为因变量，但禁止进入会改变配对含义的其他变量角色；
- 支持将多个因变量划分为若干联合分析组，例如 7d、14d、21d 三个二元 MANOVA 组；
- 与现有拆分、自定义分组、分类因素组合实验和普通自定义列保持兼容；
- 在执行审核阶段完整展示数据范围、配对质量、计算列、因变量组和最终任务层级；
- 使用独立 R 参考计算与 Python 正式计算核心进行开发期双重校对；
- 保持 v1.0 计划、工作区、结果和服务器部署兼容，不静默改变旧分析语义。

## 2. 不在本版本计划中的事项

- R 不进入正式应用运行时、桌面包或服务器部署依赖；
- 不允许配对计算列作为分类因素、协变量、随机因素、随机斜率、拆分列、对象 ID、重复因素或 EMM 因素；
- 不允许在同一个分析计划中建立多个彼此独立的配对体系；
- 不支持模糊匹配、最近邻匹配、倾向得分匹配或自动统计推断式匹配；
- 不自动判断“种植模式”等领域列应当作为因素、拆分还是仅作为匹配标签；
- 不改变简洁模式的现有工作流，配对映射和联合因变量分组仅在专业模式开放；
- 不在计划阶段改动 v1.0 计算核心、API、前端或服务器部署文件。

## 3. 核心概念与职责边界

### 3.1 配对方案

一个分析计划最多包含一个配对方案。配对方案负责定义：

- 配对分组列，例如“脱叶剂喷施时间”；
- 处理与对照的唯一映射，例如 T1→CK1；
- 必须完全相同的匹配标签，例如年份、品种、种植模式；
- 重复样本的对应规则；
- 参与配对计算的原始数值指标；
- 配对完成后保留的处理侧标签和审计信息。

只允许一个配对方案，是为了保证一个分析计划只有一个明确的数据行集合。需要使用另一套映射或匹配标签时，应新建分析计划。

### 3.2 配对计算列

配对计算列是配对方案的输出。每个计算列选择一个原始数值指标，并获得两个只读操作数：处理值和对照值。

计算公式只允许使用这两个操作数、数值常量、基础四则运算和括号。可以只使用其中一个操作数，因此“自然脱叶率＝对照值”合法。

### 3.3 普通自定义列

普通自定义列继续沿用 v1.0 规则：最多 10 列，每列最多引用 10 个可用数值列，支持基础算术和括号，不允许普通自定义列之间互相引用。

V1.5 中，普通自定义列可在配对完成后引用原始处理侧数值列或配对计算列，但配对计算列不能反向引用普通自定义列。依赖方向固定为：原始列 → 配对计算列 → 普通自定义列 → 因变量。该单向关系在结构上排除了循环依赖。

### 3.4 联合因变量组

联合因变量组用于 MANOVA 等联合响应方法。每个组代表一次独立的联合分析，例如：

- 7d：NDR7、ΔDR7；
- 14d：NDR14、ΔDR14；
- 21d：NDR21、ΔDR21。

联合因变量组不是新的统计方法，而是批量任务展开维度。未启用分组时，现有“全部所选因变量进入同一个 MANOVA”的行为保持不变。

## 4. 已确认的业务规则

### 4.1 开放范围

- 配对映射计算仅在专业模式开放；
- 联合因变量分组仅在专业模式开放；
- 简洁模式不会显示、保存或执行这些配置；
- 从专业模式切换到简洁模式时，必须先提示并自动整理相关配置。

### 4.2 配对映射规则

- 处理水平和对照水平必须一一映射；
- 同一个处理水平不能映射多个对照；
- 同一个对照水平不能被多个处理水平复用；
- 处理水平与对照水平不能重叠；
- 所有已配置映射必须在当前分析范围内同时存在；
- 每个“匹配标签组合＋映射对”内的处理数和对照数必须一致；
- 任意配置映射发生缺失、数量不一致、一对多或对照复用时，整次分析停止；
- 未被配置映射选中的分组水平不参与配对，并在预检中单独统计为“未映射排除”。

### 4.3 重复样本对应

优先支持两种明确规则：

1. 用户选择显式样本 ID：同一匹配组内按 ID 一对一匹配，重复 ID 或缺失 ID 直接报错；
2. 未提供样本 ID：按原始导入行顺序，在处理侧和对照侧分别生成组内序号。

农业参考数据使用第二种规则。系统在读取后必须保存不可变的原始行序号；预览排序、表格排序、拆分顺序和结果排序均不得改变配对顺序。预检必须明确显示“按组内原始行顺序匹配”，避免用户误以为系统使用了其他列。

### 4.4 计算公式与精度

- 每个配对计算列只能选择一个原始数值指标；
- 公式最多使用该指标的处理值和对照值两个操作数；
- 支持基础四则运算、一元正负号、数值常量和括号；
- 禁止函数调用、条件表达式、文本运算和任何列的动态查找；
- 禁止引用其他配对计算列或普通自定义列；
- 一个配对方案最多生成 10 个配对计算列；
- 结果统一保留最多 8 位小数；
- 列名去除首尾空格后必须非空，并且不能与原始列、其他配对列或普通自定义列重名；
- 除零或非有限结果按缺失值记录并在预检中显示数量，后续遵循现有完整案例规则，不伪造数值。

### 4.5 百分比与百分点

配对计算必须继承数据导入阶段已经确认的百分比解释方式。对百分号数据采用百分点显示时：

- `37%` 显示为 37；
- `24%` 显示为 24；
- `37%－24%` 显示为 13 个百分点。

预检、结果页和导出文件必须同时记录公式与单位，不能只显示数值而省略“百分比”或“百分点”含义。

## 5. 数据处理顺序

V1.5 必须使用唯一且可审计的数据处理顺序：

1. 读取数据并执行保守清洗；
2. 解析百分比和数值类型；
3. 根据自定义拆分规则确定真正进入分析的原始行范围；
4. 在该范围内校验配对映射与来源指标；
5. 建立严格的一对一处理—对照配对；
6. 生成配对计算列；
7. 生成普通自定义列；
8. 执行允许的数据校正；
9. 在配对后的处理侧数据上建立拆分组；
10. 展开联合因变量组、因素模型和拆分组；
11. 对每个任务进行数据结构验证；
12. 执行统计分析并汇总结果。

自定义拆分未分配的水平在第 3 步排除。因此，只存在于未分配水平中的配对问题不会错误阻止分析，符合“只计算已分配部分”的既有约定。

## 6. 配对后的数据形态

配对结果采用处理侧为主的一行一对结构。每一行至少保留：

- 原始处理行标识和原始对照行标识；
- 映射中的处理水平和对照水平；
- 所有匹配标签；
- 组内配对序号或显式样本 ID；
- 处理侧允许继续参与分析的原始列；
- 对照侧只读计算值；
- 配对计算列和配对质量标记。

启用配对方案后，整个分析计划都使用配对后的数据范围。系统不得让某些因变量使用配对后的 108 行、另一些因变量在同一计划中偷偷使用原始 216 行。

## 7. 与拆分功能的交互

### 7.1 匹配标签与拆分列

原始列可以同时作为匹配标签和拆分列。例如“种植模式”先确保 T/CK 在同一模式内配对，再对配对结果按模式拆分。这种用法不构成角色冲突。

### 7.2 与配对公式无关的拆分列

无关拆分列 Z 允许作用于整个包含配对计算列的分析计划：

- Z 同时是匹配标签时，处理和对照必须具有相同 Z；
- Z 不是匹配标签时，Z 只按处理侧保留值在配对后拆分；
- 预检必须明确显示“参与匹配并拆分”或“仅配对后拆分”；
- 对科学配对可能有影响但未进入匹配标签的拆分列，应给出提醒和“一键加入匹配标签”操作。

### 7.3 禁止的拆分关系

- 配对计算列不能作为拆分列；
- 配对来源数值指标不能同时作为拆分列，因为处理值和对照值可能落入不同区间；
- 普通自定义列仍不能作为独立拆分列；
- 同一原始列既是分类因素又是拆分列时，继续使用 v1.0 专业模式规则：必须有至少两个自定义组，且每组至少包含两个原始分类水平；
- 原始列不作为分类因素时，允许只定义一个非空自定义拆分组。

## 8. 与分类因素和组合实验的交互

- 配对分组列在配对后保留处理水平，因此可以作为分类因素，例如 T1、T2、T3；
- 匹配标签可以作为分类因素，也可以只用于匹配或拆分；
- 配对计算列和普通自定义列只能作为因变量；
- 因素组合实验在配对完成后展开，不重新建立配对；
- 候选因素组合不得改变配对行数；
- 如果某因素同时用于按原值拆分，导致每个任务内只剩一个因素水平，预检必须阻止该计划；
- 组合实验不是三因素模型的替代品，执行审核必须列出每一个实际因素模型。

总任务数按“联合因变量组数 × 因素模型数 × 拆分组数”计算。所有维度共同受 1000 个任务的安全上限约束；超过警告阈值时提前提示，超过硬上限时阻止运行。

## 9. 联合因变量组规则

- 仅联合响应方法显示该功能；
- 组名不能为空且必须唯一；
- 每组必须达到所选方法的最少因变量数；
- 同一因变量不能重复进入多个组；
- 启用分组后，所有已选择因变量必须归入某个组；
- 删除或重命名列时必须同步更新组；
- 组内存在失效列或不足最低数量时阻止保存和执行；
- 未启用分组时保持 v1.0 的联合分析行为；
- 保存的任务标识和导出结果必须同时包含组名及实际因变量列表。

## 10. 农业参考工作流

### 10.1 精确复现原 R 脚本

精确复现时使用：

- 配对分组列：脱叶剂喷施时间；
- 映射：T1→CK1、T2→CK2、T3→CK3；
- 匹配标签：年份、品种、种植模式；
- 重复规则：组内原始行顺序；
- 配对计算列：NDR7、ΔDR7、NDR14、ΔDR14、NDR21、ΔDR21；
- 联合因变量组：7d、14d、21d；
- 拆分列：年份；
- 分类因素：品种、喷施时间；
- 方法：双因素 MANOVA；
- 多元判据：Wilks' Lambda；
- 单变量跟进：全部效应、Type III；
- 跟进检验校正：不校正；
- 事后比较：按交互显著性分支完整比较；
- 喷施时间比较：Tukey；
- 跨任务校正：不校正，以保持与参考脚本一致。

该计划展开为 3 个联合因变量组 × 1 个因素模型 × 2 个年份，共 6 个任务，每个任务 54 个配对后观测。

### 10.2 按种植模式拆分的扩展方案

如果种植模式同时作为匹配标签和拆分列，但不作为分类因素，则展开为 3 个联合因变量组 × 2 个年份 × 3 个种植模式，共 18 个任务，每个任务 18 个观测。

该方案统计上有效，但不再是原 R 脚本的精确复现，预检必须明确标注“分种植模式分析”。

## 11. MANOVA 跟进与事后比较

当前 v1.0 Python 核心只对显著主效应执行边际比较，并只对显著简单效应继续成对比较。农业参考 R 脚本采用另一项明确规则：

- 单变量交互不显著：对两个因素都执行边际均值比较；
- 单变量交互显著：对两个方向都执行条件简单效应比较；
- 分支选择由该因变量的 Type III 交互检验决定；
- 不以主效应是否显著作为是否生成比较结果的额外门槛。

V1.5 需要新增清晰命名的“按交互分支完整比较”策略。现有保守策略继续保留为默认选项，不能为了复现 R 脚本而静默改变旧计划。

## 12. 专业模式界面设计

专业部分应合并到“数据准备与任务展开”区域，避免少量参数分散占据多个菜单。建议顺序如下：

1. 配对映射；
2. 配对计算列；
3. 普通自定义列；
4. 数据校正；
5. 拆分与自定义组；
6. 联合因变量组；
7. 因素组合实验；
8. 最终任务摘要。

配对映射采用分步编辑：选择配对分组列、建立处理—对照映射、选择匹配标签、选择显式样本 ID 或组内原始顺序、添加来源指标/公式/新列名，最后预览配对数量与前若干对结果。

针对 T/CK 命名可以提供候选映射建议，但必须由用户确认后才进入计划，不能自动执行领域推断。

## 13. 执行审核展示

执行审核必须从“数据如何变成任务”出发，而不是只列出参数。至少显示以下五层。

### 13.1 数据范围

- 输入总行数；
- 被未分配拆分水平排除的行数；
- 被未映射分组水平排除的行数；
- 真正进入配对的处理行和对照行。

### 13.2 配对质量

- 映射数量及映射表；
- 匹配标签和重复匹配规则；
- 匹配组数、处理数、对照数和成功配对数；
- 数量不一致组、重复 ID、对照复用和来源缺失数量。

### 13.3 计算列

- 新列名称、来源指标、公式、单位和小数精度；
- 缺失或无效结果数量；
- 是否被普通自定义列继续引用。

### 13.4 模型结构

- 联合因变量组和实际分类因素；
- 只匹配、不进模型的标签；
- 只拆分、不参与匹配的列；
- 多元判据、Type III 跟进、事后分支和跨任务校正。

### 13.5 任务树

农业参考精确复现计划应显示：输入 216 行；严格配对 36 组、108 对；2024 和 2025 各 54 对，每年下含 7d、14d、21d 三个任务；总计 6 个任务，全部列出有效行数、因素水平和就绪状态。

配对错误属于计划级错误，确认按钮必须禁用。一般警告可以确认后继续，但不能把错误降级为警告。

## 14. 保存、重命名与删除

- 配对方案、计算列、联合因变量组和预检摘要均进入分析计划；
- 每个配对计算列使用稳定内部标识，显示名称允许修改；
- 重命名时自动更新因变量选择、联合组和普通自定义公式中的引用；
- 删除被引用列时显示依赖清单，用户确认后级联删除或返回修改；
- 数据集变化后重新检查所有原始列、映射水平和公式来源；
- 修改映射、匹配标签、配对顺序、计算公式、拆分或因变量组后，旧结果立即失效；
- 运行记录保留当时完整计划和配对审计，不被后续修改覆盖。

## 15. 专业模式切换与旧计划迁移

### 15.1 切换到简洁模式

确认后自动清除配对方案及配对计算列、引用配对列的普通自定义列、相关因变量和失效联合组；恢复简洁模式默认高级参数；隐藏当前结果并要求重新执行。原始数据、历史计划修订和历史运行结果不得删除。

### 15.2 v1.0 计划兼容

- 新字段缺失时按“未启用配对、未启用因变量组”加载；
- 现有普通自定义列、拆分规则和因素组合计划保持原语义；
- 旧计划不会自动生成映射或因变量组；
- 如果 v1.5 计划被旧服务器读取，必须通过能力/版本检查阻止执行，不能静默丢弃新字段；
- 工作区迁移只新增可选结构，不重写原始数据或旧运行结果。

## 16. 结果与报告

页面、Excel、Markdown、JSON 和可复现记录应统一增加：

- 配对方案摘要、输入/排除/成功配对数量；
- 映射表、匹配标签和配对顺序规则；
- 配对计算列公式、单位和精度；
- 联合因变量组名与列清单；
- 因变量组、因素模型和拆分水平组成的任务标识；
- 配对失败时的完整错误说明。

R 参考校验不进入用户正式结果，只进入开发审计记录。Excel 总览应使用单独列显示“因变量组”和“联合因变量”；逐任务工作表保留完整 MANOVA、单变量跟进、简单效应和成对比较。

## 17. R 与 Python 双重校对

正式计算仍由 Python、SciPy、statsmodels 和 Patsy 完成。R 仅作为开发期独立参考实现。

## 21. 主要风险与控制

| 风险 | 后果 | 控制措施 |
|---|---|---|
| 行顺序被排序改变 | 处理和对照错配 | 保存不可变原始行序号，预检显示配对规则 |
| 拆分排除发生得太晚 | 无关水平错误阻止配对 | 先确定分析范围，再严格配对 |
| 多套配对方案并存 | 不同因变量使用不同数据行 | 每个计划只允许一个配对方案 |
| 6 个因变量被一次联合分析 | 与三个时期模型不一致 | 增加联合因变量组并展示任务树 |
| 自定义列形成环 | 无法确定计算顺序 | 固定单向依赖并禁止普通自定义列互引 |
| 因素与拆分后退化 | 模型只有一个水平 | 逐任务预检并阻止执行 |
| R 与 Python 分支不同 | 对照结果表行数和结论不一致 | 新增显式“按交互分支完整比较”策略 |
| 旧服务器忽略新字段 | 执行错误模型 | 能力/版本不匹配时阻止运行 |
| 文档与发布状态漂移 | 用户误用错误版本 | 仅在功能、回归、R 对照和浏览器门禁通过后统一切换为 1.5.0；分支推送与服务器补丁另行明确记录 |
