## 0.4.5 — 因素阶数控制、事后检验多选与显著性字母分组

### 开发目标

将候选因素数量与单个模型的因素阶数彻底分离，使普通 ANOVA 和 MANOVA 都能按 1、2、3 阶建立模型；同时将事后检验升级为可单选/多选，并生成农业论文常用的紧凑显著性字母分组。

### 主要新增与修复

- 新增统一“单/双/三因素及多候选因素组合方差分析（阶数控制）”入口；
- MANOVA 新增相同的 1/2/3 阶控制，候选因素超过阶数后按 `C(n,k)` 展开；
- 超阶组合默认关闭，只有用户确认模型数量和跨任务校正后才执行；
- Tukey–Kramer、Duncan、Games–Howell、Dunnett、Holm 等事后检验支持单选或多选；
- 每种方法独立输出成对比较和 CLD 字母体系，不混合不同方法的结论；
- 新增 `a / ab / b` 紧凑显著性字母分组，并进入网页、Markdown、Excel 和组合汇总；
- Dunnett 因只覆盖处理—对照比较，不补造完整 CLD；
- 旧 `posthoc_method` 和旧 MANOVA 计划自动迁移。

### 验证

- 后端共收集 140 项测试，按测试分区全部通过；
- 新增 6 项 CLD、阶数组合、多方法事后检验和报告专项测试；
- 所有注册方法 HTTP 预检与执行矩阵通过；
- Python 编译、Vue TypeScript 检查和 Vite 生产构建通过。

## 0.4.3 — 智能设计审查、扩展 MANOVA 与自适应混合模型

### 开发目标

把“方法能运行”提升为“设计先审查、模型按数据结构选择、结果有完整诊断与跟进”，同时覆盖单、双、三因素 MANOVA 和农业试验常用的多重比较。

### 主要新增与完善

- 新增结构化统计设计审查器，检查样本完整性、单元重复、设计平衡、残差自由度、重复测量完整性和高相关风险；
- AI 助手读取同一份设计上下文，明确当前研究问题、预计引擎和执行前动作；
- MANOVA 扩展到 1–3 个对象间因素的完整析因模型；
- 新增 Box's M、Mardia、Bartlett、相关矩阵和条件数诊断；
- 新增单变量 Type I/II/III 跟进及跨检验多重校正；
- 统一 Tukey–Kramer、Games–Howell、Holm、Bonferroni、Šidák、FDR-BH、Scheffé、Duncan、Fisher protected LSD 与 Dunnett；
- 双/三因素 ANOVA 和 MANOVA 使用模型估计边际均值，交互显著时优先提示简单效应；
- 混合设计根据平衡性、缺测和因素数量自动选择经典混合 ANOVA 或 MixedLM；
- MixedLM 支持一至两个对象间因素、对象随机截距、可选重复因素随机斜率、模型 EMM 和多重比较。

### 重要统计边界

- Duncan 和 Fisher LSD 属于较宽松方法，可能膨胀第一类错误；界面与结果均提示风险，默认仍使用 Tukey/Holm；
- 三因素 MANOVA 对完整单元、重复和残差自由度要求更高，预检会拦截空单元、秩不足和不可估计模型；
- 当前 MANOVA 仍是对象间模型，不替代多元重复测量或含随机效应的多响应混合模型；
- MixedLM 的固定效应联合检验报告 Wald χ²，不冒充经典 ANOVA F。

### 验证状态

- 后端自动化测试：125 项通过；
- 前端 TypeScript 检查和生产构建通过；
- 单/双/三因素 MANOVA、诊断、跟进、Duncan 风险提示、设计审查和混合模型自动切换均有专项测试。

## 0.3.3 — 成对处理示例模板

此版本曾加入针对示例数据的一键处理—对照工作流，并验证结果与参考工作簿一致。后续审查确认该流程具有业务特化风险，因此在 0.3.4 中从主流程移除并重构为通用批处理。

- 自动识别只能作为建议，不能作为固定语义；
- 列名和处理关系必须由当前数据与用户选择决定；
- 批处理引擎不能绑定特定作物或试验术语。

## 后续开发原则

1. 统计方法只有在执行器、预检、结果、报告和测试完整后才标记为可用；
2. AI 只负责辅助解释，不参与统计数值计算；
3. 不使用固定业务列名，所有变量角色来自当前数据和用户选择；
4. 批处理中的单个任务失败不得使其他结果丢失；
5. 高级参数默认隐藏，并提供安全默认值；
6. 所有分析保留计划、数据指纹、依赖版本和可复现信息；
7. 跨平台优先使用标准路径、原子写入和目标系统原生构建。
