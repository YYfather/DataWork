# 跨模型校正与重复运行审计

## 结论

DataWork 中存在三个容易混淆、但作用层级完全不同的概念：

1. **数据校正（Calibration）**：在模型拟合前变换数值列，例如 z-score、稳健 z-score 或基线中心化。它处理量纲、数据源系统偏差和基准对齐，不控制多重检验误报率。
2. **跨模型多重校正**：同一次执行展开多个模型任务时，对主要/总体检验形成的 p 值家族应用 Holm、Bonferroni、FDR-BH 或不校正。它处理“同时检验越多，至少出现一次偶然显著的概率越高”的问题。
3. **重复运行**：用户再次启动同一计划或在修改参数后重新运行。每次运行都有独立 run ID、结果和可复现元数据；历史运行不会被自动拼接成一个校正家族。

## 为什么需要跨模型校正

若每个原假设都按 `alpha=0.05` 判断，单个正确原假设误报的概率是 5%。当一次工作流同时检验多个模型时，至少一次偶然显著的概率会随检验数量增加。因素组合、多因变量逐项分析和按数据分层拆分都会产生这种问题。

- **Holm**：默认选择，控制家族错误率，通常比普通 Bonferroni 更有检验效能。
- **Bonferroni**：控制家族错误率，简单但较保守。
- **FDR-BH**：控制发现中的预期错误比例，适合较多探索性假设，但语义不同于家族错误率。
- **不校正**：仅适合假设彼此独立且已预先明确、或用户有外部校正方案的场景。选择后内核只按原始 p 与 alpha 判断，不生成 `p_adjusted_across_tasks` 或 `significant_adjusted`；界面、报告和导出也不显示“校正后”字段。

## 内核边界

- 校正范围是**一次批量执行**中的主要检验或总体检验。
- 模型系数、EMM、事后比较和字母分组不混入跨模型校正层；它们使用各自定义的对比校正。
- MANOVA 的 Pillai、Wilks、Hotelling–Lawley 与 Roy 按统计量名称分别成族，避免把替代判据混为一个家族。
- 启用校正时同时保留原始 p、跨模型校正 p、判断方法和检验家族；在“不校正”模式下只保留原始 p 与原始显著性，校正字段为空。
- 单模型执行不应用跨模型校正；所选方法会保存到计划中，供以后批量展开时使用。

## 组合模型与重复运行的区别

组合模型在点击确认前已经知道本次会生成哪些任务，因此系统能在同一个结果集中统一校正。重复运行则可能发生在不同时间、使用不同参数，统计内核无法推断用户是否把它们视为同一个研究假设族，也不应静默修改历史结论。

因此界面采用两种提醒：

- 同一次执行包含多个模型时，预检弹窗显示任务数量、跨模型校正方法，并要求确认。
- 已存在历史运行时，预检弹窗提示将创建新的独立运行，说明历史结果不会自动跨运行校正，并提醒避免反复试探后只报告显著结果。

## 兼容性

规范计划字段为 `cross_model_p_adjust`。旧计划中的 `combination_p_adjust` 仍会读取，并在规范化时与新字段同步，已有 API、项目和导出文件无需迁移即可继续运行。
