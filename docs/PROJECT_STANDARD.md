# DataWork 项目规范总册

本文件是 DataWork 0.4.9 的统一工程规范入口。用户操作以 `USER_MANUAL.md` 为准，统计定义以 `STATISTICAL_METHODS.md` 为准，历史审计只作为不可变验证证据，不再承担现行规范说明。

## 1. 权威文档分层

| 类别 | 权威文件 | 用途 |
|---|---|---|
| 用户操作 | `USER_MANUAL.md` | 安装、即时分析、项目工作区、结果与 AI 使用 |
| 统计规范 | `STATISTICAL_METHODS.md` | 方法、参数、假设、效应量与解释边界 |
| 工程规范 | `PROJECT_STANDARD.md` | 架构、数据流、报告、AI、安全与发布约束 |
| 测试记录 | `QUALITY_AUDIT_RECORDS.md` | 当前发布门禁与历次验证索引 |
| 开发记录 | `DEVELOPMENT_RECORDS.md` | 关键决策、修复路径与技术演进 |
| 版本记录 | `../CHANGELOG.md` | 所有版本对外变动 |
| 技术债清单 | `DEVELOPMENT_RECORDS.md` | 遗留扫描、安全移除、依赖核对与保留边界 |
| 发布操作 | `RELEASE_DEPLOYMENT_GUIDE.md` | 构建、签名、冒烟与归档 |

同一事实出现冲突时，现行权威文件优先于历史审计；统计计算结果优先于 AI 文字。

## 2. 标准目录与职责

```text
datawork/                 Python 统计核心、应用服务、Web API 与报告
frontend/                 Vue 3 + TypeScript 前端源码
desktop/                  Tauri 桌面外壳与原生构建配置
golden_datasets/          冻结输入、参考值与哈希
tests/                    单元、集成、发布与交互契约测试
scripts/                  审计、构建、清理、校验与打包工具
packaging/                PyInstaller 规范
docs/                     规范、手册、记录与历史审计
examples/                 最小示例数据
.github/workflows/        持续集成入口
```

`.venv`、`node_modules`、pytest/Vite/Python 缓存、本地审计截图、临时工作区、`dist` 和平台 sidecar 均为本地可再生产物，不进入源码发布包。

## 3. 架构与可信边界

1. Core 定义计划、角色、验证、方法注册与可复现元数据。
2. Engine 只执行显式统计方法，不静默替换失败模型。
3. Application 负责数据集、预检、执行、批量聚合、报告与工作区服务。
4. Web/CLI/Desktop 只组织交互，不另建统计计算分支。
5. AI 只解释允许的上下文；F、p、自由度、效应量、区间、排序和显著性均来自本地计算。

任何新增方法必须同时具备注册表元数据、执行器、计划校验、结构化结果、测试与文档，不得仅增加界面入口。

## 4. 数据与分析流程

标准流程为：读取文件 → 数据画像 → 明确变量角色 → 建立计划 → 预检 → 执行 → 规范结果 → 报告/导出。

- 列类型推断是建议，最终角色由计划显式记录。
- 拆分列不能同时作为模型因素。
- 因素组合会生成独立任务，并按所选跨任务方法统一校正。
- 选择“不校正”时只能显示原始 p 与原始显著性，不得生成“校正后显著性”。
- 修改方法、角色、因素、拆分或参数后，旧结果与旧 AI 报告立即失效。

## 5. 规范结果与报告

模型计算完成后先显示本地只读排序和三张规范表：

1. 表1：设计单元描述性统计（M、SD、n）。
2. 表2：主要总体/多变量检验、原始与跨任务校正判断、效应量。
3. 表3：单变量跟进、简单效应与后续比较。

效应量应并入相同任务 ID、任务条件和效应的表2行；只有无法唯一归属时才单列。`A > B > C` 仅表示估计值顺序，显著性以校正后比较、区间或 CLD 为准。完整结果保存在 canonical JSON 与 Excel 中。

## 6. AI 规则

- 默认不发送原始数据行。
- 小助手默认发送规范化证据；完整模式只追加拟合、诊断、警告、球形性、系数、provenance 与失败任务。
- AI 文字报告必须绑定当前运行，只作为解释材料。
- 证据优先级：本地完整结果 > 规范化证据 > AI 文字报告 > 用户自由描述。
- Guard 只审计 AI 可改写文字，不审计本地表号、表格值或数值型标签。
- AI 失败、空响应或守卫失败不得影响本地排序、三表和下载。

## 7. 安全、隐私与可复现性

- API 密钥不得写入项目数据库、源码、日志或发布包。
- 数据集使用 SHA-256 绑定，计划保留修订号，运行保存参数、环境与 provenance。
- 本地工作区、用户数据库、报告缓存和原始上传文件不进入源码包。
- 外部 AI 只接收用户本次明确选择的上下文。

## 8. 发布门禁

发布前必须完成：版本一致性、前端生产构建、完整 pytest、黄金数据验证、参数矩阵、数据变体、结构检查、缓存清理、源码清单和 ZIP SHA-256。平台安装包还必须在目标系统完成原生构建、签名与首次启动冒烟；源码包通过不等于所有平台安装包已签名。

当前门禁状态与历史验证统一记录在 `QUALITY_AUDIT_RECORDS.md`，具体命令见 `RELEASE_DEPLOYMENT_GUIDE.md`。

## 9. 文档治理

- 现行行为只修改权威文档；历史审计文件不覆盖改写。
- 同名重复审计只保留一份，索引文件不得复制完整正文。
- 开发决策进入 `DEVELOPMENT_RECORDS.md`，用户可见变更进入根目录 `CHANGELOG.md`。
- 每次发布更新 `QUALITY_AUDIT_RECORDS.md`、`RELEASE_DEPLOYMENT_GUIDE.md` 和源码包内 SHA-256 清单。
