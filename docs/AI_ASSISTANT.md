# DataWork AI 操作助手

## 设计原则

AI 只负责解释操作、分析计划和统计结果，不参与统计计算，也不能修改统计引擎产生的数值。

程序始终优先提供确定性说明。只有用户主动点击 **AI 优化说明** 或 **帮我读懂结果** 时才调用模型。

## 分析目的与预期效果

建立分析计划后，界面会根据当前选择实时展示：

### 分析目的

说明当前统计方法在当前变量组合下具体回答什么问题。例如：

- 比较两个独立组的均值；
- 检验多个处理水平是否存在总体差异；
- 判断两个因素是否分别影响因变量；
- 判断两个因素是否存在交互作用；
- 联合分析多个相关因变量。

### 预期效果（Expected Outcome）

说明执行后会得到什么形式的输出，例如：

- 组别描述统计；
- 均值差和置信区间；
- t、F、自由度和 p 值；
- 偏 η²或其他效应量；
- 主效应与交互效应；
- 事后比较；
- 模型诊断和风险提示。

预期效果不会在计算前猜测结果是否显著，也不会预测差异方向或具体数值。

## 智能统计设计审查

选择数据、变量角色和统计方法后，分析前检查会生成结构化设计审查，说明：

- 当前究竟研究哪些因变量、因素、协变量或重复结构；
- 预计使用的统计引擎；
- 完整样本数、观察单元数、最小单元重复数、平衡比和残差自由度；
- 空单元、单例单元、样本不足、高相关、重复缺测或不平衡等风险；
- 应优先采取的修正动作。

AI 助手读取同一份上下文进行文字解释，但统计指标和设计计数仍由确定性程序计算。即使外部 AI 未配置，设计审查也会正常运行。

## AI 结构化输出

AI 不再返回任意格式的 Markdown。程序要求模型返回固定 JSON 字段，并分别渲染为：

- 分析目的；
- 预期效果；
- 方法选择理由；
- 预期输出；
- 当前数据依据；
- 执行前检查；
- 方法边界；
- 设计审查摘要；
- 设计检查；
- 建议动作。

AI 返回格式错误时，程序自动显示内置说明。

## 结果排序与自由提问

计算完成后，内置规范报告与 AI 优化报告都会单列“组别排序与比较关系”。程序优先读取显著性字母分组和估计边际均值，其次读取描述性均值或比例，并按计算核心已有数值生成 `A > B > C` 式排序。该顺序由本地规则生成，AI 不得修改。

`>` 表示估计值从高到低，不自动表示两组差异达到统计显著；显著性仍以校正后的成对比较、置信区间或字母分组为准。共享字母表示差异未达到显著。

报告工具栏与悬浮入口均可打开 AI 小助手。用户可在聊天输入区自由提问，也可以使用当前步骤的快捷问题。

### 小助手提问上下文

每次提问都可以独立选择“数据画像”“分析计划”“当前分析结果”和“AI 生成的文字报告”。“当前分析结果”只有一个复选入口，其发送范围分为：

- **规范化证据（默认）**：发送三张规范表与统计内核已计算的前提检验；“组别排序（A > B > C）”作为其下的独立开关，默认开启；
- **完整结果与诊断**：在规范化证据之外增加模型拟合、警告、球形性、系数、可复现信息和批任务失败。

“当前分析结果”选择行显示精确到秒的结果时间，便于在连续运行后辨认当前证据。即时分析记录结果完成时间；项目运行优先显示保存的完成时间，没有完成时间时回退到开始时间。界面按浏览器本地时区显示，结果失效后旧时间会同时清除。

关闭“组别排序”后，该排序不会进入模型请求，后端也不会把排序结论补入回答。三张规范表仍作为当前结果的基础证据保留。

“AI 生成的文字报告”只有在它属于当前运行且生成成功时才能选择。该文字仅是解释材料；若它与本地统计结果或规范化证据冲突，以本地证据为准。重新执行分析后，旧文字报告会立即失效。

每条回答顶部都会显示“本回答依据”，列出实际发送的证据块，并明确提示没有发送原始数据行。若只选择 AI 文字报告，界面会建议同时加入规范化证据进行事实核对。未勾选的上下文不会进入外部模型请求。

## 配置 AI

打开网页顶部的 **AI 设置**。

### 第一步：填写连接信息

1. 选择服务商；
2. 确认 API 地址；
3. 填写 API 密钥；
4. 选择密钥保存方式；
5. 选择发送给 AI 的数据范围。

此时不需要手动猜测模型名称。

### 第二步：测试并发现模型

点击 **测试连接并拉取 Model ID**。

程序会：

1. 保存非模型连接参数；
2. 测试认证和模型端点；
3. 拉取当前密钥可见的全部模型；
4. 汇总 Model ID 和服务商能够提供的区分参数；
5. 停留在模型选择界面。

程序不会自动选择第一个模型，也不会自动继续调用。

### 第三步：手动选择 Model ID

模型表可能显示：

- Model ID；
- 显示名称；
- 所有者；
- 支持能力；
- 输入和输出 Token 限制；
- 本地参数规模；
- 量化方式；
- 模型文件大小；
- 是否可用于当前生成接口。

选中一个模型后，点击 **确认所选 Model ID**。只有完成确认后，AI 才进入可用状态。

## 支持的模型发现接口

| 服务商 | 模型发现方式 | 可展示的主要信息 |
|---|---|---|
| OpenAI | `/v1/models` | Model ID、所有者、创建信息及接口返回的能力 |
| DeepSeek | `/models` | Model ID、所有者 |
| Gemini | `models.list` | Model ID、显示名称、输入/输出限制、生成能力、思考能力 |
| Ollama | `/api/tags` | 本机模型、参数规模、量化方式、文件大小、模型族 |
| OpenAI 兼容接口 | `/models` | 取决于第三方实现 |

若 OpenAI 兼容服务没有实现标准 `/models`，程序会明确显示失败原因，并提供手动 Model ID 输入入口。

## 密钥存储

密钥可以：

- 仅保存在当前进程内存中；
- 保存到操作系统密钥库。

密钥不会写入：

- `ai_settings.json`；
- SQLite 工作区；
- 分析计划；
- 运行记录；
- 报告 ZIP；
- provenance；
- 应用日志。

## 数据隐私

默认 `metadata_only` 模式仅发送：

- 数据行列数；
- 列名和数据类型；
- 唯一值数量和缺失情况；
- 当前分析计划；
- 统计引擎结果。

默认不发送原始数据行。

用户可以主动切换为 `include_preview`，最多允许发送 5 行预览。程序仍会过滤包含以下名称的字段：

- `api_key`；
- `secret`；
- `password`；
- `token`；
- `authorization`。

## 远程部署

本地绑定时可使用 AI：

```bash
datawork-web --host 127.0.0.1
```

绑定到局域网或公网地址时，AI 默认禁用。只有部署者已经配置认证、HTTPS、访问控制和限流后，才应显式启用：

```bash
datawork-web --host 0.0.0.0 --allow-remote-ai --no-browser
```

## 常见问题

### 测试成功但没有模型

可能原因：

- 当前密钥没有模型列表权限；
- API 地址层级错误；
- 第三方兼容接口没有实现 `/models`；
- 服务返回空列表；
- 本机 Ollama 尚未安装模型。

### 为什么每次重新探测都需要选择

这是有意设计。模型清单、权限和服务端别名可能变化。重新探测后程序不会私自沿用旧模型，必须由用户确认。

### 为什么不自动推荐“最好”的模型

不同模型在费用、速度、上下文长度、隐私和可用能力方面存在差异。程序只呈现接口能够确认的信息，不替用户做未经确认的选择。

## 界面与悬浮窗交互

主页面只显示与当前计划同步更新的两项摘要：

- 分析目的；
- 预期效果（Expected Outcome）。

完整解释集中在 AI 操作助手中，包括方法选择理由、预期输出、数据依据、执行前检查和方法边界。助手现为非阻塞式悬浮窗：

- 拖动标题栏可以调整位置；
- 拖动右下角手柄可以调整宽度和高度；
- 标题栏提供最小化、右侧展开和关闭；
- 桌面端自动保存窗口位置和尺寸；
- 浏览器尺寸变化时自动约束窗口，避免移出可视范围；
- 移动端自动切换为留有安全边距的近全屏窗口，不开放自由拖动和缩放。

悬浮窗打开时不会阻断主界面，用户可以对照数据、计划和结果继续操作。“回答依据”区采用可折叠选择行，结果范围、组别排序、工作流信息和隐私提示分层展示；快捷问题横向浏览，消息区与输入区独立布局，标题栏和底部 AI 设置入口始终可访问。

AI 规范报告的数值守卫只审计外部模型可改写的叙述字段。本地引擎强制写入的组别排序、统计表格及表号不再被误当成 AI 新增数值；若 AI 连续两次未通过，报告页可展开查看具体不一致项。
