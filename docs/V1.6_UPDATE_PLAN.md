# DataWork V1.6 更新计划与实施记录

> 目标版本：`1.6.0`
> 当前基线：`1.5.0`
> 文档状态：源码实施与本地发布门禁已完成（2026-07-23）
> 适用范围：专业模式的处理—对照配对计算列；简洁模式不开放
> 发布边界：本文件固化源码更新与验收标准；GitHub 推送、Web 分支同步和服务器热补丁须在完成全部门禁后单独执行

## 1. 更新背景

V1.5 已实现处理—对照映射、严格配对、最多 10 个配对计算列、联合因变量分组、拆分继承和分层执行审核。实际使用中，连续建立 NDR、Delta 或多个时期的相似计算列时，仍需重复填写来源指标、公式、单位和精度；“单位/含义”完全依赖手工输入，容易出现 `%`、比例和百分点混用；公式也缺少安全的数学绝对值表达能力。

V1.6 不改变配对关系、样本范围或统计方法，而是在保持 V1.5 计算语义的基础上改进配对计算列的参数填写、连续新增和公式白名单。

## 2. 已确认需求

本版本必须实现以下内容：

- 配对计算列名称继续自由输入，不设置常驻名称下拉或固定业务命名；
- 名称最长 120 个字符，去除首尾空格后必须非空，并继续执行全计划唯一性检查；
- 公式模板与单位/含义选项彼此独立，选择公式不得静默覆盖单位；
- 单位/含义提供常用选项，同时允许用户输入自定义文本；
- 添加一列后，下一列先继承上一列的名称、来源指标、公式、单位和小数位；
- 继承的名称自动获得输入焦点并全选，用户必须改成唯一名称后才能保存；
- 支持从任意已有配对列执行“以此新增”；
- 编辑已有列和新增相似列必须是两个明确动作，保存编辑后不得意外创建新列；
- 新增“绝对量（保留原始尺度）”语义选项，它只描述数据尺度，不改变数值符号；
- 新增数学绝对值 `abs(x)`，它会实际改变数值；
- 允许用户输入 `|表达式|`，保存时统一规范为 `abs(表达式)`；
- 数学绝对值默认常用模板为处理—对照绝对差；
- 执行审核必须展示配对计算列的最终名称、来源、公式、单位/含义、精度及无效/缺失数量；
- V1.5 已保存计划必须保持兼容，不得静默改变既有公式或分析结果。

## 3. 不在本版本范围内的事项

- 不改变处理—对照映射、匹配标签、显式样本 ID 或原始行序配对规则；
- 不增加模糊匹配、最近邻匹配、倾向得分匹配或自动识别 CK/T；
- 不开放多个独立配对体系；
- 不改变最多 10 个配对计算列、最多 8 位小数的限制；
- 不允许配对列作为分类因素、协变量、随机项、拆分列、对象 ID、重复因素、EMM 因素或 Calibration 来源；
- 不允许配对列引用其他配对列、普通自定义列或自身；
- 不为普通自定义列开放 `abs()`；V1.6 的数学绝对值仅属于配对计算公式白名单；
- 不新增幂、取模、对数、指数、三角函数、条件表达式或任意 Python/R 函数；
- 不将 R 引入正式运行、桌面包或服务器部署依赖；
- 不在功能验收前生成正式服务器热补丁或推送发布分支。

## 4. 参数编辑器设计

### 4.1 名称

“新列名称”继续使用普通文本输入框：

- 不提供 NDR、Delta、Diff 等常驻名称选项；
- 添加成功后，继承上一列名称并自动全选，便于直接替换；
- 如果名称仍与已有配对列、原始列或普通自定义列重复，阻止保存；
- 内部稳定 ID 不随显示名称变化；
- 修改已有配对列名称时，依靠稳定 ID 识别重命名。

V1.5 已具备重命名联动机制。V1.6 必须补充回归测试，确保重命名同步更新：

- 已选因变量；
- 联合因变量组；
- 普通自定义列的来源列表；
- 普通自定义列公式中的方括号引用。

删除配对列时，引用它的普通自定义列和因变量选择继续按 V1.5 规则自动整理，历史运行结果不删除，但当前结果必须失效并要求重新执行。

### 4.2 来源指标

来源指标继续从原始数值列中选择：

- 不允许选择其他配对列或普通自定义列；
- 不允许选择正在作为拆分来源的配对指标；
- 新增相似列时默认继承上一列来源；
- 用户可以在保存前切换到另一个原始数值指标。

### 4.3 常用计算模板

公式模板只负责填充公式输入框，用户仍可继续编辑。V1.6 提供：

| 模板 | 规范公式 | 推荐解释 |
|---|---|---|
| 处理值 | `[处理值]` | 保留处理侧原值 |
| 对照值 | `[对照值]` | 对照基线，例如 NDR |
| 处理－对照 | `[处理值] - [对照值]` | 处理净效应或百分点差 |
| 对照－处理 | `[对照值] - [处理值]` | 反向差值 |
| 处理/对照 | `[处理值] / [对照值]` | 比值或倍数 |
| 相对变化 | `([处理值] - [对照值]) / [对照值]` | 无量纲相对变化 |
| 相对变化百分比 | `([处理值] - [对照值]) / [对照值] * 100` | 百分数形式相对变化 |
| 处理值的数学绝对值 | `abs([处理值])` | 对处理值取绝对值 |
| 对照值的数学绝对值 | `abs([对照值])` | 对对照值取绝对值 |
| 处理—对照绝对差 | `abs([处理值] - [对照值])` | 默认数学绝对值模板 |
| 自定义公式 | 用户输入 | 仍受完整白名单限制 |

模板与单位不得强绑定。例如选择“处理－对照”后，系统可以显示解释提示，但不能擅自把单位改为“百分点”。

### 4.4 单位/含义

“单位/含义”改为可选择也可输入的组合控件，建议项为：

- 无单位；
- `%`；
- 百分点；
- 比例（0–1）；
- 相对量；
- 绝对量（保留原始尺度）；
- 差值；
- 比值；
- 倍数；
- 与来源列相同。

用户仍可输入最长 80 个字符的自定义单位或业务解释。

必须明确区分：

- `%` 表示百分数显示；
- “百分点”用于百分数之间的算术差；
- “比例（0–1）”表示比例尺度；
- “相对量”描述相对变化或标准化结果；
- “绝对量（保留原始尺度）”只描述尺度，不执行数学取绝对值；
- 数学绝对值必须通过 `abs(...)` 或 `|...|` 公式执行。

### 4.5 小数位

小数位改为 `0–8` 的明确下拉选择：

- 默认 8 位；
- 新增相似列时继承上一列；
- 后端继续使用整数范围校验；
- 只影响该配对列最终保存值，不改变配对键或原始数据。

## 5. 连续新增工作流

### 5.1 正常添加

1. 用户填写名称、来源、公式、单位和精度；
2. 前端先进行结构检查；
3. 后端预检再次执行权威验证；
4. 添加成功后生成稳定内部 ID；
5. 当前列进入已添加列表；
6. 编辑区切回“新增”状态；
7. 编辑区继承刚添加列的全部参数；
8. 名称输入框获得焦点并全选；
9. 页面提示“已沿用上一列参数，请修改为唯一名称”；
10. 用户修改需要变化的字段后添加下一列。

### 5.2 以此新增

每个已有配对列提供“以此新增”：

- 复制名称、来源、公式、单位和小数位；
- 不复制稳定内部 ID；
- 新副本保存时生成新的稳定 ID；
- 复制后名称自动全选；
- 如果已达到 10 列上限，禁用该操作。

### 5.3 编辑已有列

“编辑”继续加载已有列并保留原稳定 ID。保存编辑后清空编辑状态，不自动创建下一列，避免用户把一次重命名误认为新增。

### 5.4 清空重新填写

“清空重新填写”清除当前未保存草稿：

- 名称；
- 来源；
- 公式和公式模板；
- 单位/含义；
- 小数位恢复为 8；
- 继承提示；
- 编辑状态和本地错误。

该操作不得删除已保存配对列。

## 6. 数学绝对值计算规范

### 6.1 允许语法

配对公式允许：

- `[处理值]`；
- `[对照值]`；
- 数值常量；
- `+ - * /`；
- 一元正负号；
- 圆括号；
- 单参数白名单函数 `abs(expression)`；
- 非嵌套、成对的 `|expression|` 输入形式。

`|expression|` 在计划模型验证阶段规范为 `abs(expression)`，预检、保存计划、结果审计和导出统一记录规范形式。

### 6.2 禁止语法

必须拒绝：

- `abs()` 空参数；
- `abs(a, b)` 多参数；
- `abs(x=...)` 关键字参数；
- `max`、`min`、`round`、`sqrt` 等其他函数；
- 属性访问、下标、推导式、Lambda、导入和任意代码执行；
- `**`、`%` 等不属于基础四则运算的运算符；
- 未配对的竖线；
- 空的 `||`；
- 任何不是处理值或对照值的列引用。

计算器继续使用 Python AST 白名单逐节点解释，不直接调用 `eval`。`abs()` 只有一个参数且递归内容仍需通过同一算术白名单。

### 6.3 缺失和无效结果

- 来源值缺失时结果为缺失；
- 除零、溢出或非有限值转换为缺失；
- 如果整列没有任何有效值，整次分析停止；
- 部分无效值记录数量并产生警告；
- `abs(NaN)` 仍为缺失；
- 绝对值不改变单位，用户必须通过“单位/含义”明确表达结果语义。

## 7. 数据流与角色边界

V1.6 保持以下单向数据流：

`原始数据 → 拆分范围预过滤 → 严格配对 → 配对计算列（含 abs） → 普通自定义列 → Calibration → 拆分/因素任务 → 统计模型`

配对计算列仍只能作为因变量。单位建议、公式模板和连续新增均为参数编辑便利功能，不得改变：

- 配对样本数；
- 处理与对照映射；
- 匹配标签；
- 拆分排列组合；
- 联合因变量组展开；
- 分类因素、协变量或随机项；
- R/Python 统计模型定义。

不存在循环依赖，因为：

- 配对列只读取一项原始指标的处理值和对照值；
- 配对列不能读取其他配对列；
- 普通自定义列可以读取配对列，但配对列不能反向读取普通自定义列；
- `abs()` 是纯数值函数，不引入列依赖。

## 8. 兼容性与迁移

### 8.1 V1.5 计划

V1.5 计划不包含新的界面草稿状态，打开后应直接按原公式执行：

- 既有四则运算公式不改写；
- 既有单位文本原样保留；
- 既有稳定 ID 原样保留；
- 既有名称和角色引用原样保留；
- 仅在用户新增或编辑配对列时显示 V1.6 辅助选项。

### 8.2 新计划被旧服务器读取

包含 `abs()` 的 V1.6 计划不得由 V1.5 后端静默执行。发布实现需要增加能力标志或 API 契约检查，旧后端必须在保存或执行前给出明确更新提示。

## 9. 执行审核与输出

预检中的配对计算列表至少展示：

- 最终列名；
- 来源原始指标；
- 规范化公式；
- 单位/含义，空值显示“未指定”；
- 小数位；
- 无效运算数量；
- 缺失结果数量。

执行审核必须使用后端返回的规范化计划和实际转换日志，不能只复述前端草稿。结果、报告和可复现附件中的公式统一使用 `abs(...)`。
