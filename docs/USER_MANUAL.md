# DataWork 0.4.9 用户使用手册

## 1. 软件简介

DataWork 是面向实验数据、科研数据和常规统计任务的跨平台分析平台。它将数据读取、变量角色选择、统计方法说明、分析前检查、统计计算、AI 辅助解释和报告导出整合到同一流程中。

DataWork 的统计数值由本地 Python 统计引擎计算。AI 是可选辅助功能，只用于解释操作和结果，不负责生成或修改统计值。

### 专业模式的数据准备

专业设置按“数据准备与拆分、模型与检验、比较与结果、批量任务”归并。自定义计算列只在专业模式出现：每个分析计划最多建立 10 个，每列最多选择 10 个原始数值列，并可组合数值常量、括号及 `+ - * / ** %`。结果实际四舍五入到小数点后最多 8 位。自定义列不能引用其他自定义列，也不能作为分类因素、协变量、随机项、对象/重复因素、拆分列或 EMM 因素，只能作为因变量；作为因变量时允许再执行 Calibration。

当原始列同时选择为拆分列和分类因素时，必须配置至少两个自定义组，每组至少保留两个因素水平。普通拆分不受此限制，可以只选择一个值作为筛选组。自定义列不单独拆分：它逐行继承其所有来源列的拆分条件，并同时受分析计划中其他拆分列约束，最终任务按这些维度的笛卡尔积展开。未分配水平不计算，空组合在预检中显示并跳过。切换回简洁模式时，界面会先确认并自动清除专业模式专属配置，不改动原始文件和历史运行。

## 2. 支持平台

- Windows；
- Linux；
- macOS；
- 本地浏览器运行；
- 受信任服务器或局域网部署；
- Tauri 桌面外壳源码。

Python 要求：3.11 或更高。

## 3. 安装与启动

### 3.1 自动安装

Windows：

```text
scripts/setup_datawork.bat
```

或 PowerShell：

```powershell
scripts/setup_datawork.ps1
```

Linux：

```bash
chmod +x scripts/setup_datawork.sh
./scripts/setup_datawork.sh
```

macOS：

```text
scripts/setup_datawork.command
```

### 3.2 手动开发安装

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[dev]"
```

Linux/macOS：

```bash
. .venv/bin/activate
python -m pip install --upgrade pip
pip install -e '.[dev]'
```

### 3.3 启动网页

```bash
datawork-web
```

默认地址：

- 软件界面：`http://127.0.0.1:8765`
- API 文档：`http://127.0.0.1:8765/docs`

### 3.4 使用独立安装包

正式发布的独立安装包应由发布者在对应操作系统原生构建并签名。用户不需要安装 Python 或 Node.js。首次启动后，桌面外壳会启动本地 `datawork-sidecar`，等待健康检查通过再显示界面。

当前源码包主要用于审计和构建；构建人员请阅读 `docs/RELEASE_DEPLOYMENT_GUIDE.md`，发布人员请逐项执行 `docs/RELEASE_DEPLOYMENT_GUIDE.md`。

遇到独立版无法启动时，先检查：安装路径是否可读、用户数据目录是否可写、防火墙或杀毒软件是否阻止本地 sidecar、端口是否被占用，以及安装包 SHA-256 是否正确。

## 4. 推荐的数据格式

### 4.1 文件类型

- CSV；
- XLSX；
- 可选旧版 XLS（需要安装 `legacy-excel` 依赖）。

### 4.2 数据表原则

- 第一行是列名；
- 每一行是一条观测；
- 每一列代表一个变量；
- 分类因素和数值指标分列存储；
- 重复测量数据建议使用长表格式，并保留对象 ID 和时间/条件列。

### 4.3 自动清理

读取后，以下列会在进入变量选择前排除：

- 完全空白列；
- 空标题列；
- `Unnamed` 占位列；
- 只包含空格的列。

程序会把排除记录写入清洗日志。

## 5. 即时分析流程

### 第一步：上传并检查数据

选择 CSV 或 Excel 文件。读取完成后检查行列数、变量类型、缺失比例、唯一值数量和被排除的空白列。程序只做保守清理，不会静默修改有效观测。

### 第二步：选择统计方法

方法卡会说明：

- 通常回答什么问题；
- 需要哪些变量；
- 主要输出；
- 适用条件和边界。

两个独立组的均值比较通常优先选择 Welch t；三个及以上独立组根据方差情况选择普通 ANOVA 或 Welch ANOVA；同一对象重复测量必须选择配对、重复测量或混合模型方法。

### 第三步：选择变量角色

按方法选择因变量、分类因素、连续协变量、随机因素、对象 ID、重复因素或拆分列。

- “恢复推荐选择”会按列类型重新应用角色建议；
- 同一列切换到冲突角色时会自动从旧角色移除；
- 修改方法、角色或参数后，旧结果会失效并显示原因；
- 拆分列通常不能同时进入模型；专业模式仅允许原始分类因素按至少两个合规自定义组同时拆分。

### 第四步：确认分析目的与预期效果

页面会根据当前方法和变量说明：

- **分析目的**：当前模型具体回答什么问题；
- **预期效果**：运行后会得到哪些统计量、效应量、后续比较和诊断。

这些说明不会提前猜测是否显著，也不会改变统计计算。

### 第五步：使用推荐参数

界面默认进入 **简洁模式**。普通用户通常不需要修改参数，只需阅读“当前采用”的推荐设置。

| 场景 | 默认选择 | 简单解释 |
|---|---|---|
| 两个独立组均值比较 | Welch t | 不强制两组方差相等，通常比 Student t 更稳妥 |
| 单因素多组 ANOVA | 自动事后比较 | 方差齐时 Tukey；方差不齐时 Games–Howell |
| 双/三因素 ANOVA | Tukey | 总体或简单效应显著后进行常规全组两两比较 |
| MANOVA | Pillai + Tukey 跟进 | Pillai 较稳健；多元显著后再定位具体因变量和水平 |
| 各处理只与 CK 比较 | Dunnett | 不比较所有处理之间，只比较处理与指定对照 |
| 领域规范要求传统分组 | Duncan | 较宽松，差异更容易显著，应同时说明误报风险 |

常见参数含义：

- **显著性标准 0.05**：p 小于 0.05 时通常认为证据达到预设阈值；它不是“结论正确的概率”。
- **Tukey**：常规全部两两比较的推荐方法。
- **Games–Howell**：方差不齐或各组样本量差异明显时使用。
- **Duncan**：较宽松，适合领域兼容或补充，不建议作为唯一结论。
- **Dunnett**：只比较各处理与明确对照；选择后才显示对照水平输入框。
- **Holm**：多次检验的逐步校正，通常比 Bonferroni 少一些保守。
- **Pillai**：MANOVA 的稳健多元判据，普通用户保留默认即可。
- **Type III 平方和**：不平衡析因设计常用，只有明确设计理由时才修改。

常用选项会直接显示一句话解释。低频选项不在简洁模式占据页面。

### 第六步：分析前检查

点击“检查并执行分析”后，程序先验证变量类型、样本量、因素水平、空单元、配对结构、模型可估计性和方法参数。

错误会阻止执行，例如：

- 缺少必要变量；
- 因素水平数量不符合方法要求；
- 样本量不足；
- 重复测量缺少对象 ID；
- 模型秩亏或没有残差自由度；
- 所有批量子任务都不可执行。

警告允许确认后继续，例如小样本、方差或正态假设风险、部分批次不可执行、混合模型可能奇异等。

### 第七步：执行分析

运行期间会显示当前阶段并禁用重复提交。请等待统计引擎完成，不要重复点击。

### 第八步：阅读和下载结果

结果页默认只展示核心检验、p 值、效应量、结论和必要的后续分析。点击“查看详细结果”可展开：

- 自由度和置信区间；
- 诊断与警告；
- 描述统计；
- 单变量跟进、简单效应和 EMM；
- 完整事后比较和显著性字母分组；
- 模型拟合指标和图形。

即时单次分析点击“生成下载文件”后，可以下载结果 Excel 和完整报告 ZIP。ZIP 包含 Markdown、规范化结果 JSON、分析计划和可复现信息。批量分析下载包含总览与逐批子表的 XLSX；项目工作区通过“生成报告”保存报告。

统计显著不等同于实际重要，应结合效应量、置信区间、实验单位、样本设计和研究背景解释。

### 5.1 专业模式

专业模式保留全部参数，包括显著性水平、备择方向、平方和类型、精确/渐近/置换算法、诊断图、EMM、多重校正、混合模型优化器、MANOVA 四种判据和随机种子。“批量拆分”在简洁模式和专业模式都可使用；专业模式额外提供类别水平合并与数值区间规则。

普通统计参数和已选拆分列在切换简洁/专业模式时不会被重置。简洁模式按拆分列的实际原值运行；专业模式可把选中列改为自定义组。切回简洁模式时只暂停使用自定义规则，仍保留原有按值拆分行为。

### 5.2 四至八因素 ANOVA 与 MANOVA

需要同时检验 4–8 个分类因素时，选择“多因素方差分析”或“多因素多元方差分析”，再设置模型因素阶数。阶数必须与实际选择的分类因素数量完全一致。

- 即时分析只拟合一个完整析因模型，不提供“分类因素组合实验”，避免按候选因素排列组合产生大量模型；
- 可以选择年份、地点、批次等独立列进行拆分；简洁模式按原值拆分，专业模式可合并类别或设置数值区间；
- 拆分列通常不进入模型；专业模式允许原始分类因素同时拆分，但必须满足至少两个自定义组、每组至少两个最终有效水平的约束；
- 高阶模型最多包含 `2^k-1` 个效应。8 因素完整模型包含 255 个主效应和交互效应，对样本量、单元重复和运行时间要求很高；
- 空单元、设计矩阵秩不足或没有残差自由度时，预检或执行会明确阻止分析。

### 5.3 单因素、双因素和三因素 MANOVA

MANOVA 要求至少 2 个相关连续因变量。新建分析直接选择：

- **单因素 MANOVA**：固定使用 1 个分类因素；
- **双因素 MANOVA**：固定使用 2 个分类因素，检验两个主效应和交互；
- **三因素 MANOVA**：固定使用 3 个分类因素，检验主效应、两两交互和三因素交互。

不再设置最小/最大阶数。达到固定因素数后继续选择因素，软件会先提示是否把它们作为候选池执行同阶组合实验。

例如 A、B、C 三个候选因素：

- 单因素 MANOVA：确认后执行 A、B、C；
- 双因素 MANOVA：确认后执行 A×B、A×C、B×C；
- 三因素 MANOVA：执行 A×B×C。

普通用户默认使用 Pillai。多元总体显著后，再结合校正后的单变量跟进、效应量、方向、置信区间和事后比较定位差异来源。

> 边界：这些是对象间 MANOVA，不是“对象间因素 × 对象内时间”的多元重复测量模型。

### 5.4 自适应混合设计

同一对象在多个时间或条件下重复测量，并同时存在对象间因素时，选择“自适应混合设计分析”。

- 完整平衡且只有一个对象间因素：自动使用经典混合 ANOVA；
- 组间不平衡、部分时间点缺测或两个对象间因素：自动切换为受试者随机截距 MixedLM；
- 结果会说明实际使用的引擎和原因；
- MixedLM 报告 Wald χ²、随机效应方差和收敛状态，不伪装成经典 F。

一般建议保留“自动选择”。强制经典模式但设计不满足条件时，预检会阻止执行。

## 6. 批量分析

批量分析不依赖固定列名。

任务数量由以下内容决定：

```text
因变量数量 × 因素组合数量 × 拆分水平组合数量
```

### 6.1 多因变量

可以一次选择多个数值指标。每个因变量作为独立任务执行。

### 6.2 任意拆分列

可以按年份、地点、批次、阶段或任意当前数据列拆分，程序不会自动选择拆分列，也不会推断其业务含义。简洁模式保持原有行为：用户选择列后，按该列实际值或多列实际值组合拆分。专业模式可进一步把多个类别水平合并成命名组，或为连续数值设置带开闭边界的区间；未纳入自定义组的记录不进入对应批次。

若因变量是自定义列，不能直接把它选作拆分列。系统根据它引用的原始列所配置的拆分，以及与公式无关的全局拆分列，共同生成任务；例如 `C=f(A,B)` 且另有 `Z` 拆分时，执行维度为 `A × B × Z`。超过 200 个展开任务会警告，超过 1000 个会阻止执行。

### 6.3 分类因素组合

四至八因素 ANOVA/MANOVA 的即时分析不提供该入口；这两种方法已经由阶数控制一个完整高阶模型，应改用专业拆分查看不同数据分层。其他支持批量的方法以及项目工作区仍按预检和任务上限规则使用因素组合。

组合实验默认关闭。达到方法常规因素上限后再点击一个因素时，软件不会静默截断，也不会立即执行，而是弹出确认窗口，说明候选因素数、每个模型使用的因素数、预计模型数和跨模型校正。只有点击“确认并启用组合实验”后才会加入该因素。

固定方法规则：

- 直接选择单因素、双因素或三因素 ANOVA/MANOVA，方法本身确定单个模型使用的因素数 `k=1/2/3`；
- 再选择 `n` 个候选因素；
- 当 `n=k` 时执行一个模型；当 `n>k` 时，确认后执行 `C(n,k)` 个独立模型；
- 旧版统一阶数计划在打开时会自动迁移到对应固定方法。

这些结果不是一个“包含全部候选因素”的超阶模型。每个组合会单独检查完整案例、水平数、空单元和模型可估计性，主要检验的 p 值再按所选 Holm、Bonferroni 或 FDR-BH 方法跨任务校正。

“跨模型多重校正”在简洁模式和专业模式中均可设置。它不仅覆盖因素组合，也覆盖同一次执行内由多个因变量或数据拆分产生的模型任务；单模型运行不受影响。数据标准化/基线中心化的 Calibration 属于模型拟合前的数据变换，与跨模型 p 值校正不是同一功能。

批量总览始终显示原始 p 和校正前是否显著。选择 Holm、Bonferroni 或 FDR-BH 时，界面再并列显示跨任务校正 p 与校正后是否显著；选择“不校正”时不生成这两个校正字段，也不会把原始判断写成“校正后显著”。

“逐批查看”中的校正结论表与结果总览采用同一口径，只列出当前批次具有有效原始 p 的主要检验或总体效应。单个因素水平的估计、简单效应、两两比较与显著性字母分组属于后续解释结果，会在该批次下方的对应区域展示，但不会作为新的总体假设重复进入跨任务校正。

规范报告不再生成内置文字正文。计算完成后先显示本地 `A > B > C` 序列化排序和三张规范表；排序与每张表均可单独展开或折叠。AI 配置可用时，系统再在后台生成简洁的文字总结并自动切换到 AI 页；AI 页只显示优化后的文字，不重复本地排序和表格，批量文字总结默认收起。AI 已经生成后再返回本地页，页面会明确提示前往第二页查看，不会继续显示“未调用外部 AI”。若 AI 未应用，报告卡片会显示原因和重试入口，但本地排序与表格始终保留。

页面顶部的五个工作流步骤可以直接点击。已经出现的步骤会滚动到对应区域并短暂高亮；如果后续步骤尚未生成，例如还未运行就点击“查看结果”，页面会回到当前能够继续处理的最近前置步骤。规范表格列数超过可视宽度时，可在表格底部使用横向滚动条，触控板和触屏也可以左右滑动。

如果页面所选校正方法与后端回显不一致，DataWork 会阻止预检或丢弃本次结果，而不是按后端的另一种方法继续展示。这通常发生在更新后仍有旧服务进程运行时；请完全退出 DataWork（包括仍在运行的后台窗口）并重新启动。

每次执行前的预检弹窗会明确显示本批模型数和校正方法。若同一即时数据或工作区计划已经运行过，弹窗还会提示这是新的独立运行：旧结果不会被覆盖，也不会与本次结果自动组成校正家族。反复修改参数并只挑选显著结果仍会增加误报风险，应预先定义假设范围或改为一次批量执行。

例如 A、B、C、D 的二阶组合会生成：

```text
A×B、A×C、A×D、B×C、B×D、C×D
```

### 6.4 批次结果页面与 Excel

网页的“结果总览”优先展示：

- 任务 ID；
- 因变量；
- 因素组合；
- 拆分水平；
- 主要统计量和原始 p 值；
- 跨任务校正 p 值；
- 显著/不显著结论。

切换到“逐批查看”可分别浏览每个任务的完整结果。Excel 按“结果总览”、各“批次_NNN”、“失败与警告”和最后的“分析设置”拆分为多个子表，详细参数不再挤占总览。

报告页采用两阶段展示：第一页“本地排序与规范表”包含确定性排序和三张统计表；第二页“AI 文字总结”只显示按当前规范结构撰写并通过守卫的文字，不再重复排序、证据概览和表格。AI 正文按章节显示，默认先呈现每节前三条结论，其余逐项统计内容收纳在“展开统计细节”中；内部证据字段名会转换为“本地只读排序”“规范表”等可读名称。AI 不能改写表格数值、父检验层级、排序次序或规范结论。

本地证据页会把 `A > B > C` 式“组别序列化结论”从普通段落中单独展示。排序优先级依次为显著性字母层级、估计边际均值、描述性均值或比例；全部排序位于一个固定可视高度的列表中，由列表整体上下滚动，不再拆分“前10项”和“其余项目”。`>` 只表示估计值从高到低，CLD 中共享字母表示差异未达到显著，最终显著性仍须读取校正后的成对比较。完整排序仍作为只读证据发送给 AI，AI 只能据此组织文字，不能重排或把大小顺序写成显著差异。

AI 文字总结的证据包包含三张规范表、只读排序、当前统计方法、数据角色、参与分析列的数据画像，以及统计内核实际计算出的结构化前提检验。模型沿“研究设计与任务范围 → 总体检验及校正 → 条件性效应与后续比较 → 本地只读排序 → 效应量 → 前提检验与解释边界”的证据链工作，重点总结跨任务稳定规律、条件性规律、方向一致性和例外；完整逐项数值由规范表承载。模型只需返回文字字段，不回传或改写本地排序和三张表，因此批量表较大时不会因重复输出表格而挤占文字总结长度。前提检验证据保留检验名称、统计量、p 值、是否满足及说明；重复测量结果还会保留可用的 Mauchly、GG/HF 参数。只有在 AI 隐私设置选择允许数据预览时，即时分析才会附最多 20 行、且仅包含参与分析列的原始数据预览；预览只帮助识别列与数值型标签，不得用于重新计算统计量或覆盖规范表。AI 文字未通过数值一致性或推断层级检查时，不合格章节会被移除；连续失败时不显示 AI 页，也不会用内置文字回填。若 AI 连续返回空正文或不完整结构，页面会直接说明未应用原因并保留本地证据。

规范报告固定附三张核心表：表1为各组或各设计单元描述性统计（M ± SD 与 n）；表2把主要总体检验与效应量放在同一行。批量结果按“任务 ID + 任务条件 + 效应”追溯，同一检验的 η²、偏 η²、ω²等指标及其区间会合并到该行的“效应量（含区间）”列；只有确实缺少唯一归属的效应量才会单列在表2末尾。MANOVA 只用预先指定的主要多变量判据驱动表2正文结论；表3为各因变量单变量跟进、简单效应和具体比较。报告顶部的证据概览会直接显示规范表、效应量、前提检验与只读排序的数量，规范控制说明按需展开。完整计算结果仍保存在 canonical JSON 与 Excel 中，但只有通过父检验和多重校正门槛的结果才进入正文解释。

单个任务失败不会使其他结果丢失。

## 7.1 计算结果与字母分组注意事项

- Tukey、Duncan、Holm、Bonferroni、Šidák、FDR-BH、Scheffé、Fisher LSD 和 Games–Howell在拥有完整组对时可以各自生成 CLD。
- 每种方法的 `a / ab / b` 只能在该方法、该因变量和该条件内部解释；不同方法的字母不能横向合并。
- Dunnett 只检验处理与对照，不知道处理组彼此关系，因此不会生成完整 CLD。
- 方差不齐的单因素数据优先选择 Welch + Games–Howell；Duncan 和 Fisher LSD 较宽松。
- 双/三因素交互显著时，应优先阅读条件简单效应及条件内字母组，不把跨条件主效应字母作为主要结论。
- MANOVA 的字母组来自显著后的单变量跟进，不是 Pillai/Wilks 多元统计量本身。

## 8. AI 助手

### 8.1 可用功能

- 解释当前步骤；
- 说明统计方法用途；
- 根据当前方法和数据角色说明分析目的；
- 说明预期会得到哪些结果；
- 辅助阅读已经计算出的结果。

结果计算完成后，展开小助手的“回答依据”可选择数据画像、分析计划、当前分析结果及当前运行的 AI 文字报告。“当前分析结果”会显示按本地时区格式化、精确到秒的结果时间，便于区分连续运行。当前分析结果默认发送“规范化证据”；只有排查模型拟合、球形性、警告、系数或失败任务时，才建议切换到“完整结果与诊断”。结果证据内的“组别排序（A > B > C）”默认开启，可以单独关闭；关闭后 AI 不会接收或补写排序结论，三张规范表仍保留。

AI 文字报告只在属于当前运行且生成成功时可选，不能替代规范化证据。每条回答都会显示实际使用的上下文；原始数据行默认不发送。重新运行分析后，旧报告不会继续用于提问。

## 10. 常见错误

### 文件读取后没有列

检查文件是否为真正的单列 CSV、是否存在异常分隔符，以及第一行是否是有效列名。0.4.2 延续并包含该修复。

### 找不到因变量

当前方法可能要求数值、二元或分类因变量。确认列的数据类型是否正确，文本数字可能需要先清洗。

### 因素无法选择

某些方法不需要分类因素，或者该列已被用作拆分列、对象 ID 或其他冲突角色。

### 重复测量无法执行

经典重复测量和混合设计要求明确的对象 ID、重复因素及完整结构。不平衡或有缺失时，通常应考虑线性混合模型。

### Logistic 回归失败

检查结局是否恰好具有所需类别、成功类别是否正确，以及预测变量是否造成完全分离。

### 批量任务部分失败

查看合并结果表中的拆分水平和错误原因。通常是某个子集样本量不足或因素只剩一个水平。

### AI 无法拉取模型

部分兼容服务没有实现 `/models`。界面会显示失败原因，并允许手动输入 Model ID 后确认。
